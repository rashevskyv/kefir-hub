# План впровадження: Оптимізація буферизації Stream для MTP та виправлення таймаутів (v0.13.290)

Цей план впровадження описує зміни для вирішення проблеми з падінням швидкості та зависанням встановлення ігор через MTP. Оптимізація полягає в усуненні операції зсування елементів вектора буфера ($O(N)$ через `vector::erase` з початку), яка створювала величезні затримки при читанні дрібними шматками і приводила до блокування MTP-сервера та таймауту з боку Windows.

## Необхідний розгляд користувачем

> [!IMPORTANT]
> - Зміна повністю сумісна на рівні API та виправляє критичний вузький потік (bottleneck) у роботі черги встановлення MTP.
> - Оскільки копіювання пам'яті в $O(N)$ на кожен цикл `ReadChunk` більше не відбуватиметься, навантаження на CPU консолі значно впаде, а швидкість запису на SD/NAND буде обмежена виключно апаратними можливостями носія.
> - Версію програми буде ітеровано до `0.13.290` у [CMakeLists.txt](file:///d:/git/dev/sphaira/sphaira/CMakeLists.txt).

### [Компонент: Інсталяційний стрім-міст]

#### [MODIFY] [install_stream_menu_base.hpp](file:///d:/git/dev/sphaira/sphaira/include/ui/menus/install_stream_menu_base.hpp)
- Додати приватне поле `size_t m_read_offset{0};` до структури `Stream` для збереження поточної позиції читання у векторі буфера `m_buffer`.

#### [MODIFY] [install_stream_menu_base.cpp](file:///d:/git/dev/sphaira/sphaira/source/ui/menus/install_stream_menu_base.cpp)
- **Конструктор `Stream::Stream`**: ініціалізувати `m_read_offset` значенням `0`.
- **Метод `Stream::ReadChunk`**:
  - Замінити перевірки `m_buffer.empty()` на перевірку `m_buffer.size() == m_read_offset` (означає, що всі записані дані зчитані).
  - Копіювати дані з `m_buffer.data() + m_read_offset` замість початку вектора.
  - Збільшувати `m_read_offset` на кількість зчитаних байтів (`size`).
  - Додати логіку очищення буфера: якщо `m_read_offset == m_buffer.size()`, то виконати `m_buffer.clear()` та скинути `m_read_offset = 0` (очищає вектор, зберігаючи його `capacity` для уникнення повторних алокацій).
  - Якщо буфер не порожній, але зсув читання став занадто великим (наприклад, `>= 4 МБ`), зсунути лише залишок даних до початку вектора за допомогою `std::memmove` і зробити `m_buffer.resize(...)` та `m_read_offset = 0`. Це гарантує обмеженість споживання оперативної пам'яті (до ~10 МБ).
  - Прибрати виклик `m_buffer.erase(m_buffer.begin(), m_buffer.begin() + size)`.
- **Метод `Stream::Push`**:
  - Замінити перевірки переповнення `m_buffer.size() >= MAX_BUFFER_SIZE` на `(m_buffer.size() - m_read_offset) >= MAX_BUFFER_SIZE` (для точного визначення обсягу незчитаних даних у буфері).

### Ручна перевірка (після збірки NRO)
1. Скомпілювати нову версію програми в середовищі WSL (`make` чи `build.sh`).
2. Запустити її на консолі, підключити USB-кабель.
3. Провести встановлення гри (NSP/NSZ) розміром > 1 ГБ через MTP Install.
4. Переконатися, що встановлення проходить повністю (до 100%), швидкість не падає до нуля, а USB-підключення не розриється.
