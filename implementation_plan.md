# План впровадження: виправлення автозапуску MTP та усунення конфлікту з USB HDD (usbHsFs)

Цей план впровадження описує зміни для вирішення проблеми з автоматичним запуском MTP при підключенні кабелю та падінь/помилок запуску MTP через конфлікт з бібліотекою `usbHsFs` (режим USB Host для HDD).

## Необхідний розгляд користувачем

> [!IMPORTANT]
> - Оскільки USB-контролер Nintendo Switch не може працювати одночасно у режимах USB Host (для підключення HDD/флешок) та USB Device (MTP/USB-інсталяція для підключення до ПК), ці режими тепер є взаємовиключними в коді програми.
> - При ввімкненні MTP фоновий сервіс роботи з USB HDD (`usbHsFs`) буде автоматично вимикатися, а при вимкненні MTP — знову запускатися (якщо опція HDD увімкнена в налаштуваннях).
> - Те саме стосується меню встановлення по USB (`usb_menu` та `dbi_menu`): під час їхньої роботи HDD-сервіс буде тимчасово зупинятися, щоб не блокувати USB-порт.
> - Версію програми буде ітеровано до `0.13.278`.

### [Компонент: Ядро програми та фонові сервіси]

#### [MODIFY] [haze_helper.cpp](file:///d:/git/dev/sphaira/sphaira/source/haze_helper.cpp)
- Додати підключення заголовка `#include <usbhsfs.h>`.
- У функції `Init()` перед ініціалізацією `::haze::Initialize` перевіряти, чи увімкнено HDD (`App::GetHddEnable()`). Якщо так — викликати `usbHsFsExit()` для звільнення USB-порту.
- У разі помилки ініціалізації MTP у `Init()`, якщо HDD увімкнено — знову ініціалізувати його: `usbHsFsInitialize(1)` (з урахуванням налаштування `App::GetWriteProtect()`).
- У функції `Exit()` після зупинки MTP, якщо HDD увімкнено — запускати його: `usbHsFsInitialize(1)` (з урахуванням налаштування `App::GetWriteProtect()`).

#### [MODIFY] [app.cpp](file:///d:/git/dev/sphaira/sphaira/source/app.cpp)
- У конструкторі `App::App` змінити перевірку ініціалізації HDD: не запускати `usbHsFsInitialize(1)` під час старту програми, якщо активовано автозапуск MTP (`App::GetMtpEnable()`), щоб уникнути миттєвого блокування USB-порту.

### [Компонент: Інсталятори USB та DBI]

- У деструкторі меню перезапускати HDD через `usbHsFsInitialize(1)` (з урахуванням налаштування `App::GetWriteProtect()`), якщо HDD увімкнено, а MTP не буде повторно активовано.

### Ручна перевірка (після збірки NRO)
1. Скомпілювати нову версію програми у WSL.
2. Перевірити автозапуск MTP на приставці при ввімкненому HDD у налаштуваннях: при підключенні кабелю до ПК MTP має успішно визначатись.
3. Перевірити поведінку при монтуванні папки через файловий менеджер: MTP має стартувати без помилки "Failed to start MTP!".
4. Перевірити роботу DBI-меню та USB-меню: при підключенні до ПК з цих меню з'єднання має встановлюватися стабільно, без конфліктів зі сторони фонового HDD.
5. Перевірити роботу USB HDD у файловому менеджері після виходу з режимів USB/MTP.
