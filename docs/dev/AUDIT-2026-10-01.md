## Знахідки

### F1. Контекст з'їдають службові документи (критично для дешевої моделі)
`plan.md`, `task.md`, `walkthrough.md`, `audit.md` — одна й та сама історія v0.13.871→922, переписана в 3–4 формах.
`AGENTS.md` вимагає читати й оновлювати всі чотири на кожен delivery. Плюс `README.md` 72 KB і `GRAPH_REPORT.md` 3 446 рядків.
Старт сесії коштує ~65 k токенів до першого корисного кроку.
**Рішення:** один `plan.md` (лише активна робота), `docs/dev/CHANGELOG.md` (1–3 рядки на версію, append-only),
`AGENTS.md` ≤ 90 рядків, `CLAUDE.md` = `@AGENTS.md`. Правило: ніколи не `cat` звіт графа цілком — лише `graphify explain/path`.

### F2. Python contract-тести не тестують продукт
Два типи: (a) `test_static_review_*` — regex-ассерти на текст C++ (`assert "m_cancel_cb()" in c_text`);
(b) «behavioral» — симуляції стейт-машин, переписані на Python у `contract_fixtures/`, тестують самі себе.
Вони «проходили» в delivery, де C++ не компілювався. 28 k рядків підтримки без захисту від регресій.
Справжні тести вже є і працюють: `tests/*.cpp` (pure logic у headers, `g++ -Werror`), `check_dead_symbols.py`,
`test_patch_libhaze.sh`, `test_patch_ftpsrv.sh`, i18n key-parity.
**Рішення:** статичні grep-контракти видалити; для кожної Python-моделі — або host C++ тест проти реальної функції
(вирізавши pure-core у header без libnx, як уже зроблено для `install_plan.hpp`, `path_util.hpp`), або видалити.

### F3. MTP transfer/cancel — неявна стейт-машина на 7 глобалах, 3 потоки
`haze_internal.hpp`: `g_mtp_transfer_active/aborted/seq/handled_seq/ui_alive/pbox/current_filename` під `g_mtp_ui_mutex`,
логіка переходів розмазана по `StartMtpProgressBox` (lambda + cancel callback + completion callback), `haze_callback`,
`Init`, `Exit`. Кожне з 8 переписувань латало один race і відкривало інший; жодне не перевірено на консолі.
`g_is_running` (`haze_internal.cpp:33`) — plain `bool`, читається з UI-потоку в `IsRunning()/IsRecovering()`,
пишеться в `Init/Exit` — data race (тоді як `g_should_exit` — `std::atomic_bool`).
**Рішення:** спочатку апаратний baseline (checklist), потім витягти `MtpTransferState` як pure struct з явними
подіями → діями, покрити host-тестом, і лише тоді підключити назад.

### F4. Політика «не компілювати» + «кілька комітів, потім збірка»
Користувач свідомо обрав batching. Ризик: 5 з 24 комітів — виправлення збірки. Пом'якшення без зміни політики:
`-Werror` для first-party коду (зараз закоментовано), host-тести після змін pure logic (секунди, не NRO-збірка),
checkpoint збірки не рідше ніж кожні 5 комітів або в кінці фази.

### F5. Гігієна репозиторію
У git трекаються: `remote_log.txt` (112 KB), `.codex-tmp/*.bak/*.json`, `.grok/`, `.agents/` (попри `.gitignore`).
`sphaira/graphify-out/` — 35 MB дубль, заборонений самим `AGENTS.md`. Скіл `test-build` у двох копіях.
`CLAUDE.md` відсутній — Claude Code не підхоплює `AGENTS.md`. 19 непушених комітів, 4 stash.

### F6. Потокова безпека поза MTP
45 глобальних `bool/u64 g_*` без `std::atomic`: `ftpsrv_helper.cpp:144 g_is_running`, `log.cpp g_thread_running/g_thread_stop`,
`net.cpp g_cache_valid/g_cache_value`, `account_link.cpp g_daemons_terminated`, `i18n.cpp g_languages_scanned`, `auto_update.cpp g_notify_shown`.
Кожен треба класифікувати: один потік → лишити; кілька → atomic або під наявний mutex.
19 `threadCreate` проти 22 `threadWaitForExit` — перевірити парність на всіх шляхах виходу.

### F7. Небезпечні рядкові операції
45 викликів `strcpy/strcat/sprintf`. Більшість, імовірно, з літералами; ті, що пишуть у фіксований буфер зі змінним джерелом, — переробити на `snprintf`/`std::string`.

### F8. Граф має діри в core
Graphify не розпарсив 8 заголовків: `defines.hpp` (L255), `net.hpp` (L32), `nxlink.h` (L47), `ams_su.h` (L36), `hbl/source/main.c` (L27) +3.
Це макро-важкі файли; для моделі це означає, що `graphify explain Result` неповний. Низький пріоритет, але варто глянути `defines.hpp:255`.

### F9. Неоднозначні імена

і правило для моделі: завжди кваліфікувати шлях.

### F10. `App` — god object (841 ребер)
Не рефакторити (ризик > користь), але заборонити додавання нових статичних членів/глобального стану в `App`; нова логіка — у вільних функціях модуля.
