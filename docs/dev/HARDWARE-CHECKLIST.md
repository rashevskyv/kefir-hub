# Апаратний чекліст (Switch + ПК)

Виконує користувач. Заповнюється після кожного build checkpoint, що зачіпає MTP/USB/saves.
Формат рядка: `- [ ] A1 … — v0.13.XXX: PASS | FAIL (що саме сталося)`. Baseline: **v0.13.934, 2026-10-01** — розділи A–B пройдено (+/−), C ще ні. Кожен FAIL має задачу H1–H8 у `plan.md`.
Ці сценарії не перевірялися з v0.13.903 по v0.13.922 (20 версій) — тому спершу baseline, потім зміни.

## A. MTP — передача та скасування (історія v0.13.903–922)
- [+] A1 Копіювання 1 NSP на «Install» з ПК → встановлення стартує, плашка прогресу з'являється і закривається після завершення, не зависає на останньому файлі.
- [-] A2 Копіювання папки з 3+ файлами на microSD → усі файли на місці, плашка оновлює ім'я файла, закривається один раз у кінці. → **plan H3**
	- Перекидання папки ні до чого не призводить, а перекидання чотирьох файлів одним махом працює. Треба зробити, щоб перетягання самої папки також працювало. Бо в подальшому ми матимемо необхідність встановлювати переклади перетягуванням. 
- [+] A3 Скасування на Switch (B у ProgressBox) під час передачі → передача припиняється ≤ 2 с, неповний файл видалено, MTP лишається видимим на ПК **без** перепідключення кабелю, USB не переходить у host mode. → **plan H1** — v0.13.949: PASS (MTP сам перепідключається в device mode)
- [-] A4 Скасування на ПК (Cancel у провіднику Windows) під час передачі → Switch не зависає, плашка закривається, наступна передача працює без перепідключення. → **plan H2**
	- Віконечко закривається, віконечко на консолі, там де малюється прогрес встановлення, воно лишається і поступово швидкість з поточної знижується до нуля. І вже коли доходить до нуля, тоді воно закривається. Хоча на комп'ютері вже віконечко закрите. Вважаю, це трошки неправильним. 
	- v0.13.949: FAIL — те саме (~хвилину висить, потім файл зникає); скасований на ПК A1 після цього ще й перезапускав MTP і ламав наступне копіювання. Виправлено у v0.13.952 (class Cancel Request), перевірити на v0.13.953.
- [+] A5 Відключення кабелю під час передачі → додаток не падає; після підключення MTP знову працює. — v0.13.949: PASS
- [+] A6 Скасування під час установки NSP (modal підтвердження доступне) → установка зупинена, сесія звільнена, наступний NSP встановлюється. → **plan H1** — v0.13.949: PASS
- [+] A7 Повторні натискання під час скасування: B → «+», далі ще B/«+», поки плашка закривається → без краху, скасування одне. Подвійне B неможливе за дизайном (друге B закриває діалог підтвердження), тому окремо не проганяється: єдина проблема з baseline була та сама, що в A3 — v0.13.949: закрито разом з A3.
	- Не дуже розумію, як подвійне скасування могло би спрацювати, якщо після того, як я натискаю Б, я маю натиснути плюс для того, щоб підтвердити скасування. Тож, коли я двічі натискаю Б, я першим разом ініціалізую плашку, де маю вибрати, скасувати чи ні, і друге натискання B відміняє скасування. Ну і проблема та сама, яка в А3 після скасування треба перепідключати консоль або передіргуючи кабелем, або через меню. 
- [+] A8 Скасування в «idle window» (одразу після завершення файла, до початку наступного) → плашка не з'являється повторно, нічого не зависає.
- [x] A9 (знято: маршрутизацію видалено у v0.13.941, plan H8) Маршрутизація: NSP/NSZ/XCI/XCZ у корінь «Nintendo Switch» → потрапляє в Install; інші файли → microSD як фізичні файли. → **plan H8 (відкладено)**
	-	Маршрутизація не працює, ми начебто вирішили забити на це. 
- [+] A10 Згорнута плашка (L3) під час MTP-установки показує правильний прогрес за розміром пакунка.
- [+] A11 Вимкнення MTP у налаштуваннях під час передачі → коректна зупинка; увімкнення знову працює при підключеному VBUS. — v0.13.949: PASS
