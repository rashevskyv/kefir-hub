# Перенос профілю і наіграних годин між консолями

Робоча інструкція. Перевірено чужими руками (Erista → Mariko, duckbill / 4PDA / GBAtemp).
Наші гіпотези позначені як **Г**. Експерименти — як **Е**.

Мета: один профіль + його години + іконки/назви ігор + можливість далі копити час.
Не мета: злити два різні профілі в один.

Хабовський шлях: **бекап розшифровує на джерелі**, **TegraExplorer на цілі шифрує ключами цілі і кладе на місце**. HacDiskMount / hactoolnet не потрібні.

---

## 1. Що де лежить

Усі ID — system save на розділі **SYSTEM** (`SYSTEM:/save/<id>`).

| Save ID | Owner | Що всередині | Для переносу |
|---|---|---|---|
| `8000000000000010` | account | Профілі: ім’я, UID, аватар, baas/nas, токени | **Обов’язково**, якщо треба сам юзер |
| `8000000000000011` | account | idgen | Часто їде парою з 0010. **Г:** без нього UID на цілі можуть роз’їхатися |
| `80000000000000F0` | ns / pdm | `pdm:/` Play Data. `PlayEvent.dat` — увімкнули, сон, пробудження, запуск/згортання ігор | **Обов’язково** для годин |
| `8000000000000041` | ns | LRU іконки HOME для недавно граних | **Г:** іконки в логу активності. Беремо, якщо на цілі іконки «Unknown» |
| `8000000000000120` | ncm | Кеш CNMT **прошивки** | **Не чіпати** — зламає OS |
| `8000000000000121` | ncm | Кеш CNMT ігор на **USER/NAND** | Не playtime. Копія на іншу консоль = «ігри встановлені, яких немає» |
| `8000000000000124` | ncm? | За повідомленнями — те саме для **SD** | Як 0121: не копіювати всліпу |

Години **не** в USER-сейвах ігор і не в JKSV-бекапі гри. DBI / NX-Activity-Log читають pdm (`pdmqry*`), дані живуть у **00F0**.

`PlayEvent.dat` — журнал подій по часу. Два профілі з **різних** консолей у один файл = накладки «в ту саму секунду запущено дві різні гри». Розшифровка в txt буває, пакувальника назад — ні. Тому **не мерджимо** профілі.

---

## 2. Крипт

Сирий файл `SYSTEM:/save/80000000000000F0` зашифрований ключами **цієї** консолі (BIS + save MAC). Вставити його в NAND іншої без перепідпису = TegraExplorer «скопіював, emuMMC не грузиться», розмір 0–1 КБ, Atmosphere crash.

Тому Хаб **ніколи не копіює сирий blob**. Він знімає **внутрішні файли** (Horizon сам розшифрував). На цілі TegraExplorer відкриває **вже існуючий** сейв цілі (`readsave`), пише файли всередину, `commit()` підписує ключами цілі.

Після 17.0.0 system save має бути в індексі FS (`8000000000000000`). Сире підкладання файлу в `SYSTEM:/save/` **минувши** CreateSave — ризик brick (SciresM). Скрипт **не створює** новий blob, якщо його немає.

`device_key` потрібен лише для ПК-репаку (додаток нижче). Для шляху Хаб + TegraExplorer — ні.

## 3. Шлях Кефіра (те, що в програмі)

Працює з **emuNAND** (рекомендовано) або sysNAND. Бекап SYSTEM цілі до будь-якого запису.

### 3.1. Бекап на джерелі (Horizon)

Tools → Users → **Backup profiles & play hours**.

Хаб зупиняє account/BCAT/OLSC (для 0010/0011) і за потреби pdm/ns (для 00F0/0041), монтує system save через FS, копіює **розшифроване** дерево файлів на SD:

```
/config/kefir/nand_transfer/<YYYYMMDD_HHMMSS>/
  manifest.json
  README.txt
  restore.te
  8000000000000010/     baas/, nas/, avators/, …
  8000000000000011/     якщо відкрився
  80000000000000F0/     PlayEvent.dat і сусіди
  8000000000000041/     якщо відкрився
```

Копія `restore.te` також лежить у `/config/kefir/nand_transfer/restore.te`.

Пак **зберігає UID**. Це не «Restore user pack» (той створює **нового** юзера → години не підхопляться).

Якщо 00F0 не відкрився — закрити ігри, повторити. Без F0 профілі поїдуть, години ні.

### 3.2. Рестор на цілі (TegraExplorer, не Horizon)

00F0 на живій системі зайнятий pdm/ns. Писати його з Хаба під Horizon — **Г**, поки не підтверджено. Рестор робить скрипт.

1. Бекап SYSTEM цілі (Hekate).
2. Скопіювати всю теку пака на SD **цілі**.
3. Інжектнути **TegraExplorer** (на SD цілі мають бути ключі / Lockpick).
4. Відкрити теку пака, запустити `restore.te` (або скрипт з `/config/kefir/nand_transfer/`).
5. Обрати пак, потім **emuMMC SYSTEM** або **sysMMC SYSTEM**.
6. Скрипт для кожного ID: `readsave(bis:/save/<id>)` → `write` внутрішніх файлів → `commit()` (підпис ключами цілі).
7. Ребут CFW. Перевірити профілі і DBI Activity Log.

Скрипт **не** кладе сирий файл у `SYSTEM:/save/`. Якщо blob на цілі немає — цей ID пропускається (не створюємо індекс).

**Г:** TegraScript Save не вміє delete. Зайві файли цілі всередині сейву можуть лишитися. Якщо на цілі багато зайвих локальних юзерів — краще прибрати їх Хабом до рестору.

Повна заміна F0 = години цілі **зникають**. Очікувано. Далі pdm пише нові події в цей журнал.

F0 без 0010 з тими самими UID = Unknown Players. Тому в паку обидва.

0121/0124 не копіюємо.

## 4. Два сценарії профілю

### A. Той самий UID (Backup profiles & play hours + restore.te)

0010 + 00F0 цілком. Лог активності показує імена, години як на джерелі, далі копиться.

### B. Новий UID (Restore user pack)

Хаб створює **нового** юзера. 00F0 зі старого UID дасть Unknown Players або нуль годин. Для переїзду консолі **не** цей пункт.

---

## 5. Що перевіряти руками (пріоритет)

Робити на **emuNAND**, з бекапом SYSTEM.

| # | Дія | Очікування | Ломає? |
|---|---|---|---|
| **Е2** | Хаб: Backup profiles & play hours на джерелі | Тека з `PlayEvent.dat` і `baas/` | Ні, якщо тільки читання |
| **Е3** | На цілі: `restore.te` тільки F0 | Години стали як на джерелі; профілі цілі | Години цілі |
| **Е4** | Е3 + 0010 з тими самими UID | Імена в логу, не Unknown | Профілі цілі = джерело |
| **Е5** | Тільки 0010, F0 не чіпати | Профілі змінюються, години цільові | Профілі |
| **Е6** | Restore user pack (новий UID) + старий F0 | Unknown Players / нуль годин | Години |
| **Е7** | Пограти годину після вдалого Е4 | Час додається до старого журналу | Ні |

Що скинути з експерименту: чи відкрився F0 з Хаба, список файлів у паку, лог `restore.te` (wrote/errors), скрін DBI Activity Log до/після, чи є Unknown Players, чи копиться час.

---

## 6. Що не робимо

- Мердж двох PlayEvent.dat.
- Копія 0120/0121/0124 «щоб ігри підтягнулись».
- Сирий blob TegraExplorer / HacDiskMount без репаку ключами цілі.
- Перенос на чистий OFW / бан через онлайн із чужим pdm.

Ігрові сейви — окремо (вже вміємо: DBI zip + `fsCreateSaveDataFileSystem` на цілі). Вони не несуть годин.

## Додаток. ПК-шлях (якщо Хаб/TE не зайшов)

Потрібно: Hekate, Lockpick (з `device_key` на **обох**), HacDiskMount або NxNandManager, hactoolnet, `prod.keys` **джерела** і **цілі**. Бекап SYSTEM обох NAND.

```
hactoolnet.exe -k source_prod.keys -t save 8000000000000010 --outdir out/0010
hactoolnet.exe -k source_prod.keys -t save 80000000000000F0 --outdir out/00F0
hactoolnet.exe -k dest_prod.keys -t save dest_80000000000000F0 --repack out/00F0
```

На цілі: **видалити** старий blob, **потім** вставити вже перепідписаний. Не overwrite поверх.

Lockpick_RCM 1.9.11 на OLED інколи не знімає `device_key` — без нього ПК-репак на Mariko не збере. Для шляху Хаб + TE цей ключ не потрібен.
