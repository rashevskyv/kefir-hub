# Актуальний канонічний план

Цей файл відновлено після повного аудиту Git-історії `plan*`, `task*`,
`REFACTOR_PLAN*`, `implementation_plan.md` та файлів у `archive/`.

## Правило цілісності

- Кожна задача має стабільний ID і посилання на джерело в історії.
- Виконані задачі не видаляються: їх переносять до `archive/task_archive.md` зі
  статусом, комітом і коротким доказом.
- Відкладені або заблоковані задачі не архівуються як виконані.
- Ручна перевірка на Switch не прирівнюється до автоматично підтвердженої.

## Стан пакета v0.13.238

Пакет підготовлено 2026-07-16 після аудиту останніх п'яти комітів і повної
історії `plan*`, `task*` та архівів.

Завершено в цьому пакеті:

- відновлено загублені історичні задачі зі стабільними `HIST-*` ID;
- зміцнено HTTP/devoptab: безпечний GET retry/resume, перевірка truncation і
  фінального flush, коректна обробка EOF та локальних I/O-помилок;
- додано Game Details з реальними NCM компонентами й точковим NSP dump;
- додано Runtime Mode UX, Applet-профіль вебсервера, listener diagnostics,
  loopback self-test та добровільний Title Mode forwarder;
- повністю вилучено аудіо-runtime, BGM, системні звуки та `libpulsar`;
- автентифікацію foreground-вебсервера свідомо не додано за рішенням власника.

Поточний пріоритет: завершити `HIST-61A`, далі `HIST-61B` → `HIST-61C` →
`HIST-60` → `HIST-62`. DBI-задачі `HIST-54..56` виконуються після Games-блоку,
якщо не з'явиться критична регресія.

## Definition of Done

Задача може бути перенесена в архів лише коли:

1. реалізація відповідає критеріям у цьому файлі;
2. Release-збірка проходить;
3. автоматичні перевірки записані в `tests.md`;
4. апаратні сценарії або пройдені, або явно залишені `[ ]` як manual gate;
5. `task.md` і `archive/task_archive.md` оновлені в тому самому коміті.

#### HIST-61A — Overview і компоненти

- Окремий Game Details у стилі Sphaira: обкладинка, назва, видавець, Title ID,
  display version, підтримувані мови та наявність LayeredFS.
- Вкладка Components: Base, Update, DLC і DataPatch з version, storage, size,
  content count та ticket/rights status.
- Вкладки Tickets і Saves без повторного сканування даних у `Draw()`.
- Реалізовано 2026-07-16: Details відкривається по A, читає реальні NCM записи,
  показує часткові помилки замість тихого пропуску, а dump із Details завжди
  обмежений поточною грою й перевіряє помилки формування NSP.
- Поточні `Contents folder` і `Save quota` навмисно не називаються активним
  LayeredFS або фактичним save usage; точні статуси лишаються в цій задачі.

#### HIST-61B — безпечні операції над контентом

- Контекстні дії для конкретного компонента: dump NSP, integrity verification,
  content information та, після окремої перевірки NCM API, NAND ↔ SD move.
- Mount/Open content на першому етапі робити read-only; будь-який запис потребує
  підтвердження і повторної перевірки вільного місця.
- Delete, reset required version і force language винести в Advanced із чітким
  описом наслідків та можливістю скасування.

#### HIST-61C — saves, tickets і DLC

- Показувати всі saves гри за користувачами, тип, використаний/доступний розмір;
  відкривати наявний Save Manager для backup/restore замість дублювання логіки.
- Показувати rights IDs, тип ticket і key generation без відкриття секретних
  ключів у звичайному UI.
- DLC unlocker реалізовувати лише після окремої перевірки формату, сумісності та
  безпечного rollback; не позначати готовим лише через наявність dump ticket code.

### HIST-PLAYER — вбудований медіаплеєр

Джерело: втрачений розділ 8.3, згаданий у `archive/plan_archive.md:365`.

Статус: **заморожено**. Не починати без окремого погодження; поточний шлях
`Play with NXMP` залишається підтримуваним рішенням.
Вбудований audio runtime і фонова музика вилучені 2026-07-16; якщо колись буде
погоджено плеєр, він має додаватися окремо, без автоматичного повернення BGM.

### HIST-WEB-APPLET — вебсервер у Applet/Title Mode

- Зберегти спробу запуску в Applet Mode з меншими socket buffers, але показувати
  користувачу обмеження пам'яті та інструкцію Title takeover: утримувати R під
  час запуску встановленої гри, дочекатися hbmenu/Kefir Hub і запустити Sphaira.
- Додати добровільне встановлення forwarder поточного NRO, якщо користувач не має
  зручного Title Mode entry point. Не встановлювати NSP без підтвердження.
- Автозапуск після install дозволити лише коли інсталятор надійно повертає точний
  application ID створеного forwarder; до цього запускати його з HOME вручну.
- Додати діагностику URL/IP/port і відрізняти помилку старту listener від Wi-Fi
  client isolation або недоступності консолі з іншого пристрою.
- Реалізовано 2026-07-16: видима довідка Runtime Mode, пункт-заміна для
  недоступного в Applet системного браузера, попередження про NSO scan fallback,
  інструкція на екрані сервера, журнал socket/bind/listen і два worker-и замість
  трьох у Applet, а локальний HTTP loopback self-test відрізняє справний listener
  від зовнішньої мережевої проблеми. Залишилася ручна перевірка client isolation.
- Автентифікацію не планувати: за рішенням власника сервер працює лише на явно
  відкритому foreground-екрані. Це рішення не скасовує валідацію шляхів/запитів.
