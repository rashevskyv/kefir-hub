## 8. Відеоплеєр на базі NXMP (mpv) та мережеві джерела файлів

**Статус:** Нова велика фіча. Розбита на 3 фази — виконувати ПО ЧЕРЗІ, кожна фаза самодостатня і корисна сама по собі. НЕ починати фазу 3 без явного погодження, вона найризикованіша.

**Довідка по NXMP (результат дослідження репозиторію https://github.com/proconsule/nxmp):**
- NXMP — відеоплеєр для Switch на базі **libmpv** (обгортка: клас `libMpv` у `source/libmpv/libmpv.h/.cpp` — `loadFile()`, `loadFileLive()` для стрімів, `Pause/Resume/Stop/seek`, отримання кодеків/бітрейту/доріжок, перемикання відео/аудіо/субтитрів `setVid/setAid/setSid`).
- HW-декодування H264/HEVC/VP8/VP9/MPEG2 до 4K@60 через **кастомні форки**: FFmpeg від averne (гілка `nvtegra`), mpv від averne (бекенд deko3d, `mpv/render_dk3d.h`), libuam. Усі вони збираються вручну як portlibs — інструкція в `BUILD.md` nxmp (конкретні configure-прапори там).
- Рендеринг: deko3d (у sphaira рендеринг теж deko3d — через nanovg-deko3d, `sphaira/CMakeLists.txt:193`), тобто GPU-стек сумісний, але mpv рендерить у власний render context, який треба інтегрувати в кадр sphaira.
- Мережеві джерела NXMP: SMB (libsmb2), NFS (libnfs), SFTP (libssh2), FTP, HTTP(S), m3u8/HLS, UPnP, Enigma2. Реалізовані як **devoptab-файлсистеми** в окремому сабмодулі **`proconsule/nxmp-devoptabs`** (smb2fs, nfsfs, sshfs, ftpfs, m3u8fs, libarchivefs) + браузери каталогів у `source/remotefs/` (HTTPDir на curl, UPNP, Enigma2). libsmb2/libnfs збираються з `nxmp/libs/*/PKGBUILD` зі switch-патчами.
- CBR/CBZ/PDF — через mupdf (`source/pdfloader/`); плейлисти і позиції відтворення — sqlite3.
- **Slave-режим:** `nxmp/source/main.cpp:310` — якщо запустити nxmp.nro з аргументом (`argc>1`), він одразу відкриває файл `argv[1]`. Це офіційний механізм «запусти цей файл у плеєрі».

**Що вже є в sphaira (на що спиратися):**
- Запуск .nro з аргументом-файлом: `nro_add_arg_file()` (`sphaira/source/nro.cpp:270`), приклад використання — запуск NXthemes_Installer у `themezer.cpp` (`nro_launch(GetNroPath())`).
- Список відео-розширень уже визначений: `VIDEO_EXTENSIONS[]` (`sphaira/source/ui/menus/filebrowser.cpp:95` — mp4, mkv, m3u8, avi, ts тощо).
- Система мережевих локацій: `sphaira/include/location.hpp` — `location::Entry{name, url, user, pass, bearer, pub_key, priv_key, port}`; stdio-монтування (`StdioEntry`) для USB через usbhsfs.
- curl-шар з підтримкою `webdav://` (`sphaira/source/download.cpp:582, 944`).

### Фаза 8.2 — Мережеві джерела (SMB/NFS/SFTP/FTP/HTTP) у файловому менеджері

**Мета:** у filebrowser можна додати джерело (Samba-папку, NFS-експорт, SFTP/FTP/HTTP-сервер), переглядати його як звичайну теку і: (а) запускати відео через nxmp, (б) копіювати файли, (в) встановлювати ігри (це автоматично працюватиме через пункт 3.2/3.3, бо конвеєр спільний).

**Кроки:**
1. **Клонувати референс:** `git clone https://github.com/proconsule/nxmp-devoptabs` (сабмодуль nxmp; у .gitmodules URL записаний як git@ — використовувати https-варіант). Вивчити структуру: кожна ФС (`smb2fs`, `nfsfs`, `sshfs`, `ftpfs`) — це devoptab-драйвер (POSIX open/read/stat/dirnext поверх бібліотеки протоколу). Побудувати graphify-граф по клону (`/graphify <шлях>`) для орієнтації.
2. **Бібліотеки:** додати в збірку sphaira libsmb2 та libnfs (див. `nxmp/libs/libsmb2/PKGBUILD` + `switch.patch`, `nxmp/libs/libnfs/PKGBUILD` + `libnfs.patch`; збирання — через dkp-makepkg АБО FetchContent+патчі в CMake, за зразком того, як sphaira уже підтягує залежності в `CMakeLists.txt`). libssh2 і curl — вже є в devkitPro portlibs (curl sphaira вже лінкує). **Порядок упровадження протоколів: почати ТІЛЬКИ з SMB** (найзатребуваніший), решту — після того, як SMB пройде приймання; кожен протокол — окремий коміт.
3. **Порт devoptab:** перенести `smb2fs` з nxmp-devoptabs у `sphaira/source/utils/` (за зразком уже наявного кастомного devoptab: `sphaira/source/utils/devoptab_nca.cpp`). Init: `smb2fs_mount(url, user, pass)` → з'являється девайс `smb2:/`.
4. **Локації:** розширити `location::Entry` (`location.hpp`) типом протоколу (розпарсити зі схеми url: `smb://`, `nfs://`, `sftp://`, `ftp://`, `http://`). У filebrowser у списку локацій (де зараз SD/USB) показувати збережені мережеві джерела; при виборі — монтувати devoptab (з таймаутом і `App::PushErrorBox` при невдачі), при виході — розмонтовувати.
5. **UI додавання джерела:** у сайдбарі filebrowser пункт "Add network location"_i18n → форма через `swkbd::ShowText` (послідовно: назва, адреса сервера, share/шлях, логін, пароль) → зберегти через `location::Add()`. Пароль в ini зберігається відкритим текстом — так само робить nxmp; зафіксувати це обмеження в описі коміту.
6. **Продуктивність:** читання по мережі повільніше SD — переконатися, що копіювання йде через `threaded_file_transfer` (`sphaira/source/threaded_file_transfer.cpp`) з буфером ≥1МБ; листинг великих тек — з індикатором завантаження.
7. **Зв'язка з nxmp:** для відеофайлу на мережевій локації пункт "Play with NXMP" передає **оригінальний URL** (`smb://user:pass@host/share/file.mkv`), а не devoptab-шлях — nxmp сам уміє ці схеми (його mpv/ffmpeg зібрані з мережевими протоколами). Це знімає потребу в спільному маунті.

**Критерії приймання:** додавання SMB-джерела з UI → тека видна у filebrowser → відео з неї запускається у nxmp по URL → `.nsp` з неї встановлюється штатним конвеєром; відключення сервера під час перегляду теки не крешить sphaira (чиста помилка).

**Підводні камені:**
- devoptab-слоти обмежені (32 на процес, частина зайнята romfs/sdmc/ums) — монтувати мережеві ФС ліниво і розмонтовувати при виході з локації.
- libsmb2 на Switch потребує патча (є в nxmp/libs) — без нього не збереться/не працюватиме DNS-резолв.
- Не блокувати UI-потік на мережевих операціях: листинг — у фоновому потоці (подивитися, як filebrowser вже робить асинхронний скан тек).
- SMB1-сервери (старі NAS) libsmb2 не підтримує — у повідомленні про помилку з'єднання радити SMB2/3.

### Фаза 8.3 — Вбудований плеєр у sphaira (епік, окреме погодження перед стартом)

## 15. Автоматизація збору та перекладу sysmodules (Майбутній етап)

**Мета:** Інтегрувати процес автоматичного оновлення бази sysmodules та перекладу нових локалізаційних рядків безпосередньо в команду `make` збірки проекту.

### Кроки реалізації:

1. **Оновлення бази sysmodules з Gist**:
   - Інтегрувати в `Makefile` (або скрипт підготовки збірки) команду, яка перед компиляцією забирає з Gist найсвіжішу версію файлу `homebrew_sysmodules.txt` (за URL: `https://gist.githubusercontent.com/ndeadly/a4b8c01bb453028cd0008f282098f696/raw/homebrew_sysmodules.txt`).
   - Після цього запускається генератор `update_module_catalog.py` для оновлення описів та структури даних.

2. **Автоматичний переклад локалізацій (на базі ШІ)**:
   - Створити окрему Python-програму автоматичного перекладу (за прикладом пайплайну з `dbi_patcher` — `src/core/ai_client.py`).
   - Програма повинна:
     - Читати англійський файл локалізації (`en.json`) та порівнювати його з іншими мовами (наприклад, `uk.json` та іншими майбутніми локалізаціями).
     - Виявляти нові ключі, що були додані до `en.json`, але відсутні в інших мовах (зокрема, нові описів модулів з `i18n_en_candidates.json` виду `module.<TID>.description`).
     - Надсилати нові рядки на переклад до локального сервера Gemini (`localhost:8081` / Web2API або Gemini Proxy) із системним промптом щодо збереження контексту Nintendo Switch та правил локалізації.
     - Автоматично дописувати перекладені рядки у відповідні файли локалізації, зберігаючи сортування JSON.

3. **Інтеграція в `Makefile`**:
   - Додати ці кроки у ціль `prepare` або передскладальний крок `make`, щоб при кожній збірці переклади та бази даних оновлювались автоматично без участі розробника.
